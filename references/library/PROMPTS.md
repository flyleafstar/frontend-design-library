# 前端设计使用方法与提示词模板

这是灵感库四类提示词的可迁移版本。Skill 会读取并填充对应模板；也可手工复制并替换 `[填写…]`。素材库路径以 `--library`、`FRONTEND_DESIGN_LIBRARY` 或随包 `references/library/` 为准。

## 四步使用方法

1. **先选用途，再定主风格**：先选后台、研究报告、产品官网或个人主页，再确定一种适合用户与任务的主风格。收藏 2–3 个互补参考，避免把不同风格平均混在一起。
2. **打开来源，指出借鉴区域**：进入具体页面或提供截图，标明想借鉴的首屏、导航、表格或正文排版。风格示意卡用于选方向，真实页面用于确认细节。
3. **复制模板，补齐真实内容**：选择下面的页面类型，复制完整提示词。替换方括号中的用户、任务、内容路径和参考链接；一个主参考决定整体，其他参考补充局部。
4. **浏览验收，再定向迭代**：要求直接实现并在浏览器检查。修改时按“位置 → 问题 → 目标 → 保留项”反馈，说明想保留的设计，减少反复重做。

## 三类参考分工

| 角色 | 用法 |
| --- | --- |
| A · 视觉参考 | 决定整体气质：配色、字体层级、留白与图像处理。明确其中一个为主参考。 |
| B · 结构参考 | 提供信息组织：导航、内容顺序、表格、筛选与主要操作的位置。只借鉴指定区域。 |
| C · 代码底座（可选） | 提供模板或组件起点。先检查技术栈、依赖与许可，沿用当前项目的架构约定。 |

一个主参考决定整体风格，其他参考只补充指定区域。尽量提供具体页面或截图，并说明想借鉴的部分。未填写参考时，模板会让 Codex 从本地目录选择 2–3 个来源并实际访问；这一步不表示素材库已自动访问或验证这些页面。

## 分类提示词

### 后台

面向反复使用的业务工作台，让用户快速找到记录并完成操作。

建议从企业工作台、极简留白开始；重点是任务、状态与信息密度。

```text
请使用 frontend-design 技能设计并实现后台页面；若不可用，按以下要求完成。

【目标与内容】
项目：[填写名称]；主要用户：[填写岗位]；核心任务：[填写最重要的操作]。
内容来源：[填写文件路径或字段]；必须保留：[填写现有功能与约束]。缺失数据明确标为示例。

【参考与风格】
A 视觉：[填写链接或截图及借鉴的配色、字体、留白]。
B 结构：[填写链接及借鉴的导航、表格或操作区]。
C 代码底座（可选）：[填写仓库或组件]，先检查技术栈与许可。
以 A 为主参考，B/C 只补充指定部分。采用[填写主风格]，优先清晰层级、舒适文字与适当信息密度。
未指定参考时，读取当前选定素材库目录中的 catalog.json，选 2–3 个来源并访问具体页面；说明选择理由，访问失败不猜测内容。

【页面与交互】
首屏突出待办和关键记录，包含导航、搜索、常用筛选、表格、状态与详情入口。按任务提供加载、空结果和错误反馈；高影响操作需确认。权限和后端未接入时明确标为演示，不伪造保存成功或真实访问控制。

【实现与验收】
已有项目沿用架构、技术栈与组件；新建独立展示页优先 HTML/CSS/JavaScript。说明真实功能与示例边界。兼顾桌面、手机、键盘、焦点、标签与对比度，检查表格溢出。先简述结构和方向，再直接实现；在浏览器验证搜索、筛选、详情与移动布局，提供预览入口。
```

### 研究报告

先组织有证据的内容，再用阅读层级与图表帮助读者形成判断。

建议从编辑刊物、极简留白开始；重点是结论、证据和长文阅读。

```text
请使用 frontend-design 技能设计并实现研究报告网页；若不可用，按以下要求完成。

【目标与内容】
主题：[填写研究主题]；主要读者：[填写读者]；核心任务：[填写要支持的判断]。
材料：[填写文件路径或来源]；范围与截止日期：[填写范围和日期]。先研究出有证据的内容，再渲染成网页；材料不足标为待核验，不补造结论。

【参考与风格】
A 视觉：[填写链接或截图及借鉴的字体、留白、图文节奏]。
B 结构：[填写链接及借鉴的摘要、目录或证据排列]。
C 代码底座（可选）：[填写仓库或组件]，先检查技术栈与许可。
以 A 为主参考，B/C 只补充指定部分。采用[填写主风格]，保持正文易读、图表标注清晰。
未指定参考时，读取当前选定素材库目录中的 catalog.json，选 2–3 个来源并访问具体页面；说明选择理由，访问失败不猜测内容。

【页面与交互】
组织为“30 秒结论 → 3 分钟重点 → 深入证据”。提供目录锚点、关键图表、方法与局限、来源清单；区分事实、推断和假设。数据注明口径、单位、来源与日期，示例图表显著标注。支持打印，避免图表和段落被截断。

【实现与验收】
已有项目沿用架构、技术栈与组件；新建独立展示页优先 HTML/CSS/JavaScript。说明真实功能与示例边界。兼顾桌面、手机、键盘、焦点、标签与对比度。先简述结构和方向，再直接实现；在浏览器检查目录、来源链接、窄屏图表与打印预览，提供预览入口。
```

【参考与风格】

## 迭代反馈模板

按“位置 → 问题 → 目标 → 保留项”给反馈，保持每轮修改范围明确。

```text
请在现有页面基础上调整，按以下反馈完成：

【位置】[填写页面与具体区域，例如项目列表顶部筛选区]
【问题】[填写观察到的问题，例如首屏看不到项目记录]
【目标】[填写希望达到的效果，例如常用筛选放在一行，其余条件收起]
【保留项】[填写配色、导航、内容、功能等必须保留的部分]
【验收】[填写要检查的操作与屏幕尺寸]

先简述修改范围，再直接实施。保留现有真实内容与可用功能，不把功能改成静态演示；完成后用浏览器验证目标效果、键盘操作和手机布局，并说明实际修改与验证结果。
```

## 使用提示

- 通过本 Skill 的 `scripts/select_references.py --type ...` 获取完整模板与候选；它只读取文件，不访问外网。
- 未填写参考时，以 `--library` 或 `FRONTEND_DESIGN_LIBRARY` 指定的目录为准；都未指定时使用随包 `references/library/`。
- `frontend-design` 为可选设计技能，没有安装也可按模板继续。
- 本包不包含网页版界面、浏览器草稿、收藏或第三方页面截图。需要离线视觉参考时，请提供有来源的本地截图。
- 随包原始来源核验日期为 2026-10-24；实际使用代码或服务前核查当前原站与许可。
